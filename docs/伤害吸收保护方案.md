# 伤害吸收（黄心）保护 —— 方案定稿

> 目标：做成一个**独立 mod**，拦截其他 mod 绕过伤害吸收直接对玩家造成伤害 / 击杀的行为。
>
> 总原则：只在**服务端**、只在**玩家**、只在**有伤害吸收**时介入；其余一律放行。

## 术语

**护盾 = 伤害吸收（Absorption）= 黄心**。全文统一称「吸收」。

## 1. 目标行为

| 情况 | 结果 |
|---|---|
| 无吸收 | 完全走原版，正常扣血 |
| 吸收 > 0，伤害 D < A | 扣吸收，血不动（原版已如此） |
| 吸收 > 0，伤害 D = A | 吸收清零，血不动（原版已如此） |
| 吸收 > 0，伤害 D > A | 吸收清零，**溢出 (D − A) 丢弃，血不动** |
| 玩家有吸收，被任意 mod 直写扣血 | 只扣吸收，血不动 |
| 玩家血 > 0，被强制 `die()` | 拒绝死亡 |

## 2. 原版行为对照（为什么要改）

`setHealth` 只做 `clamp(0, maxHealth)` + 写 data，**完全不碰吸收**：

```java
public void setHealth(float p_21154_) {
    this.entityData.set(DATA_HEALTH_ID, Mth.clamp(p_21154_, 0.0F, this.getMaxHealth()));
}
```

扣吸收的逻辑**只存在于 `actuallyHurt`**：

```
actuallyHurt:  先扣吸收 (L1622 / L914) → 再 setHealth 扣血 (L1635 / L924)   ← 吸收只在这条链上
setHealth:     直接写血，完全不碰吸收                                        ← mod 绕过路径
```

- `LivingEntity.actuallyHurt`：`L1621-1638`
- `Player.actuallyHurt`（覆写）：`L913-930`
- 唯一「溢出入血」点：`L1635` / `L924` 的 `setHealth(getHealth() - f1)`

因此需求 = **原版 − 「溢出进血」那一步**；而 mod 直接 `setHealth(0)` 时护盾是 0 还是 20 都一样执行，血直接变 0、护盾原封不动 —— 这就是「绕过吸收」。

## 3. 三层设计

### 第一层：伤害结算溢出保护

**落点**：`Player.actuallyHurt`（必需）。
（可选扩展：再加一份 `LivingEntity.actuallyHurt` 覆盖全生物，代码同构。）

```java
@Mixin(Player.class)
public abstract class PlayerDamageOverflowMixin {
    @Shadow public abstract float getAbsorptionAmount();
    @Unique private boolean tcc$hadShield;

    @Inject(method = "actuallyHurt(Lnet/minecraft/world/damagesource/DamageSource;F)V",
            at = @At("HEAD"))
    private void tcc$captureShield(DamageSource source, float amount, CallbackInfo ci) {
        // 进入本次伤害时有吸收，且不是 /kill、虚空这类必死伤害
        this.tcc$hadShield = this.getAbsorptionAmount() > 0.0F
                && !source.is(DamageTypeTags.BYPASSES_INVULNERABILITY);
    }

    @Inject(method = "actuallyHurt(Lnet/minecraft/world/damagesource/DamageSource;F)V",
            at = @At(value = "INVOKE",
                     target = "Lnet/minecraft/world/entity/LivingEntity;setHealth(F)V"),
            cancellable = true)
    private void tcc$blockOverflow(DamageSource source, float amount, CallbackInfo ci) {
        if (this.tcc$hadShield) {
            ci.cancel();       // 吸收已被原版清空；溢出丢弃，血不动
        }
    }
}
```

> **无敌帧保留**：不改动 `invulnerableTime`，清盾后仍受原版 0.5s 无敌帧约束。

### 第二层：`setHealth` 直写拦截

**落点**：`LivingEntity.setHealth`，挂 `LivingEntity` 类，用 `instanceof Player` 过滤。

```java
@Mixin(LivingEntity.class)
public abstract class SetHealthGuardMixin {
    @Shadow public abstract float getHealth();
    @Shadow public abstract float getAbsorptionAmount();
    @Shadow public abstract void setAbsorptionAmount(float amount);
    @Shadow public int tickCount;

    @Inject(method = "setHealth(F)V", at = @At("HEAD"), cancellable = true)
    private void tcc$guardSetHealth(float newHealth, CallbackInfo ci) {
        if (this.level().isClientSide) return;          // 仅服务端
        if (!(this instanceof Player)) return;          // 仅玩家
        if (Float.isNaN(newHealth)) return;             // NaN 修复放行
        if (this.tickCount <= 0) return;                // 读档 / 构造期放行
        if (newHealth >= this.getHealth()) return;      // 只拦「降血」，治疗放行

        float shield = this.getAbsorptionAmount();
        if (shield <= 0.0F) return;                     // 无吸收放行

        float delta = this.getHealth() - newHealth;                 // 想扣的血量
        this.setAbsorptionAmount(shield - Math.min(delta, shield)); // 只扣吸收
        ci.cancel();                                                // 血不动
    }
}
```

**与第一层不冲突**：第一层已把 `actuallyHurt` 内那次 `setHealth` 调用 cancel → 本层收不到；无吸收时本层自动放行。

### 第三层：死亡兜底

**落点**：`LivingDeathEvent`（Forge 官方可取消钩子，无需 Mixin）。

`die()` 第一行即为 `if (ForgeHooks.onLivingDeath(...)) return;`（LivingEntity `L1304` / Player `L586`）。

```java
@EventBusSubscriber(modid = "...", bus = EventBusSubscriber.Bus.FORGE)
public final class PlayerDeathGuard {
    @SubscribeEvent
    public static void onLivingDeath(LivingDeathEvent event) {
        if (!(event.getEntity() instanceof Player player)) return;
        if (player.level().isClientSide) return;
        if (player.getHealth() > 0.0F) {          // 血还在，不该死
            event.setCanceled(true);
        }
    }
}
```

- 血 = 0 → 放行（真正的死亡）。
- 血 > 0 → 取消。**不需要回血**，因为只在血有值时才取消。
- 事件会 fire 两次（Player 一次、super 一次），本逻辑幂等，无副作用。

## 4. 覆盖矩阵

| mod 行为 | 谁兜住 |
|---|---|
| 只 `setHealth(0)` | 第二层拦住 → 血不为 0 → die 不触发 |
| 只 `die(src)`（血 > 0） | 第三层取消 |
| `setHealth(0)` + `die(src)` | 第二层保血 + 第三层取消（双保险） |
| 正常致死伤害 | 不介入：血合法归 0 → die 放行 |
| `/kill`、虚空 | 第一层放行 `BYPASSES_INVULNERABILITY` → 血归 0 → die 放行 |
| NaN 修复 / 治疗回血 / 读档 | 第二层全部放行 |

## 5. 边界与放行

| 边界 | 处理 |
|---|---|
| `/kill`、虚空（out_of_world） | 归 `BYPASSES_INVULNERABILITY`，**放行**，否则有吸收时会死不了 |
| NaN 修复 | `Float.isNaN` 放行，零误伤 |
| 读档 / 构造期 | `tickCount <= 0` 放行，避免读档血量错乱 |
| 治疗 / 免死回血（往上写） | `newHealth >= getHealth()` 放行 |
| 怪物死亡 | 第二层 `instanceof Player` 过滤 → mob 完全走原版 |
| 护甲 / 抗性 | 拦截点在护甲、魔法减免**之后**，照常参与 |
| 客户端 | 三层均限定服务端，不干扰血条同步 |

## 6. 已知取舍

- 第三层「血 > 0 一律不死」会顺带挡掉某些 mod 的「处决」机制 —— 符合目标。
- 第二层只拦「有吸收时向下写血」，无吸收时零影响。
