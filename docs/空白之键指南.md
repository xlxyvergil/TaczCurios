>
> 覆盖：物品定位与作用、联动规则原理、数据包填写规则、从零生成数据包、示例规则集、排错清单、可复制的文案模板。

## 1. 饰品定位

### 1.1 一句话说明

**空白之键本身没有任何固定属性。它是一把「属性转换器」：当指定饰品槽里装着指定饰品时，读取佩戴者本人的某项属性总值，按倍率转写到佩戴者的另一项属性上。转换关系全部由服务端数据包定义，所以同一件物品在不同整合包里表现完全不同。**

> ⚠️ 最容易被写错的一点：**被转换的数值不是那件饰品的属性，而是佩戴者自己的属性总值。**
> 指定饰品只起「开关 / 钥匙」的作用——它出现了，这条规则才生效；数值来源始终是角色面板上的 `source` 属性总值（基础值 + 所有既有修饰符，包括这件饰品本身和其它饰品、buff 提供的加成）。
> 换句话说：那件饰品的**具体增益数值不重要**，重要的是「它存不存在」决定规则命中；而真正被乘倍率的，是转换发生时你角色面板上的源属性总值。

| 项目 | 值 |
|---|---|
| 物品 id | `tcc:kongbai_zhijian` |
| 槽位 | `tcc_kb`（独立槽位，1 格，槽位图标直接用物品自身贴图，见 [TaczCurios.java#L129](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/TaczCurios.java#L129)） |
| 稀有度 / 堆叠 | `RIFT` 裂隙级 / 1（[TccItems.java#L186](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/registries/TccItems.java#L186)） |
| 获取方式 | **无合成配方**。由整合包通过 `/give`、任务书、战利品或自定义配方发放 |
| 绑定 | 首次装备即绑定（NBT `IsBound` / `BoundPlayer`），他人无法装备 |
| 死亡掉落 | 不掉落（`ALWAYS_KEEP`；女仆佩戴时按默认规则） |
| 卸下成本 | **免费**，不需要崩坏结晶（覆写了 `canUnequip`，见 [KongbaiZhijian.java#L106](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/items/curios/kongbai/KongbaiZhijian.java#L106)） |
| 佩戴者 | 玩家（`canEquip` 要求 `instanceof Player`） |
| 前置依赖 | 至少一条命中规则，否则装不上 |

### 1.2 玩家看到的行为

持在手里或戴在身上，tooltip 有三种状态（文案见 [zh_cn.json#L18](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/resources/assets/tcc/lang/zh_cn.json#L18)）：

| 状态 | 显示 |
|---|---|
| 没戴在身上 | `装备后按联动规则生效` |
| 戴了，但当前没有任何命中规则 | `未绑定联动饰品` |
| 戴了且命中 | `已绑定饰品：<饰品名>` + `联动规则：<源属性> × <倍率> → <目标属性>` + 一行蓝色当前实际加成 |

也就是说**规则对玩家是可见的**：玩家能直接看到"我戴的哪件饰品、把什么属性转成了什么属性、现在值多少"。这条 tooltip 由服务端把规则表下发给客户端渲染（[NetworkHandler.java#L90](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/network/NetworkHandler.java#L90)），服主不需要为客户端额外准备数据包。

### 1.3 设计意图（写进说明文档的卖点）

1. **不锁死数值**：物品不带硬编码属性，规则是外部数据。改一条 JSON 就能把这个物品从"暴击伤害转枪伤"改成"移速转射速"，不用改代码、不用重发模组。
2. **实时跟随**：写入的是"源属性总值 × 倍率"的重算结果，不是一次性快照。换枪、吃 buff、换别的饰品导致源属性变化时，加成会立刻跟着变，并在攻击时兜底对齐一次。
3. **赛季制友好**：同一件物品在 A 赛季可能很弱、在 B 赛季可能很强，全靠整合包决定，做平衡调整不必删物品。
4. **可热更**：`/reload` 后在线玩家自动重算（[CuriosItemEventHandler.java#L109](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/event/CuriosItemEventHandler.java#L109)），旧的修饰符按 uuid 精确清除，不残留。

## 2. 联动规则的原理

### 2.1 一条规则回答四个问题

一条规则由「**门控条件**」和「**数值转写**」两段拼成，两段的来源完全不同：

```
门控条件（只决定这条规则是否生效）
  slot  → 看哪个饰品槽
  curio → 该槽内必须存在的饰品（完整注册名，逐字符比较）

数值转写（数据全部来自佩戴者本人）
  source  → 读佩戴者该属性的实时总值（基础值 + 全部修饰符）
  ratio × operation → 写入佩戴者 target 属性，用独立 uuid 记账
```

也就是说 `curio` **不提供被转换的数值**，它只是一个开关。同一个 `slot` 里可以同时放多件不同饰品，各条规则按各自的 `curio` 独立判定。

命中条件（[KongbaiZhijian.java#L377](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/items/curios/kongbai/KongbaiZhijian.java#L377)）：

- 佩戴者在 `slot` 这个槽位上必须存在该槽位（没有这个槽 / 0 格 → 整组规则跳过）；
- `slot` 槽位里必须装着 id 恰为 `curio` 的物品（逐字符比较注册名）；
- `curio` **不能**是 `tcc:kongbai_zhijian` 自己（防自指，写了永不触发）。

### 2.2 数值公式

```
写入值 = 佩戴者.getAttributeValue(source) × ratio
```

`getAttributeValue` 是**总值**（基础值 + 所有既有修饰符），所以源属性被别的饰品/buff 堆高时，这一条也会跟着涨。

举例：规则 `暴击伤害 → 枪械伤害，ratio 0.6`，你的暴击伤害总值 100%。
→ 转换出 100% × 0.6 = 60%，按 `multiply_base` 加到枪械伤害上。
此时如果《致命暴击》额外给了你 +30% 暴击伤害，总值变 130%，转换结果立刻变成 78%——**不是**把《致命暴击》自身那 30% 单独拎出来乘 0.6。

> 所以它是「角色属性重定向」而不是「饰品属性复制」：规则的输出永远取决于你**当前整个人**的源属性面板。

### 2.3 operation 三种运算的实际含义

| `operation` | 写入方式 | `ratio` 的读法 | 适用场景 |
|---|---|---|---|
| `addition` / `add` | 直接加绝对值 `+value` | `0.5` = +0.5 点 | 攻速、弹速、暴击率等"点" |
| `multiply_base`（默认） | 加基础值百分比 `+value × 基础值` | `0.5` = 基础值的 +50% | 伤害、护甲等"百分比" |
| `multiply_total` | 参与总乘区 | `0.5` = 乘区 +50% | 想要完整乘算放大的场景 |

> ⚠️ `ratio` 不是"最终变成 50%"，而是"按上面表格的方式加多少"。tooltip 里 `addition` 显示绝对值、其它显示百分比。

### 2.4 保护性行为

| 情况 | 行为 |
|---|---|
| `source` 与 `target` 是同一属性 | 跳过并清掉该 uuid（防止自我叠加放大） |
| 算出来是 0 | 移除该 uuid 的修饰符，不写 0 值修饰符 |
| 数值与运算方式都没变 | 不重建修饰符（幂等，避免每 tick 触发属性重算） |
| 数据包删掉了某条规则 | 按物品 NBT 里留存的旧快照仍能精确清除 |

## 3. 数据包填写规则

### 3.1 文件位置

```
数据包根/data/<任意命名空间>/tcc_links/<任意文件名>.json
```

- 装载器：[AttributeLinkRegistry.java#L50](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/link/AttributeLinkRegistry.java#L50)，`SimpleJsonResourceReloadListener`，目录名固定 `tcc_links`。
- 目录下**所有文件合并成一张全局规则表**；可以按主题拆多个文件，也可以建子目录归类。
- 命名空间随意（`tcc`、`my_pack` 都行），不同数据包用不同命名空间不会互相覆盖。
- 只放服务端即可。
- 模组**不自带任何默认规则**：没装数据包时规则表为空，日志为 `槽位数=0, 规则数=0`，此时空白之键装不上去（见第 6 章第 10 条）。

### 3.2 顶层结构

```json
{
  "links": [
    { "slot": "...", "curio": "...", "source": "...", "target": "...", "ratio": 0.5, "operation": "multiply_base", "uuid": "..." }
  ]
}
```

`links` 缺失 → 整个文件**静默跳过**（不报警告），这是最常见的"我明明放了文件但没生效"。

### 3.3 字段说明

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `slot` | 是 | string | 触发槽位 = Curios 槽位标识。本 mod：`tcc_slot`(8 格) / `tcc_3rd`(1) / `tcc_tdk`(1) / `tcc_kb`(1)；也可用其它已注册槽位（`charm` / `ring` / `belt` / `hands` / `neck` / `back` / `body` / `head`） |
| `curio` | 是 | string | 触发饰品 id，**完整注册名** `namespace:path`，例 `tcc:lethal_crit` |
| `source` | 是 | string | 源属性 id，读**佩戴者**该属性的总值（不是饰品提供的加成） |
| `target` | 是 | string | 目标属性 id，写入修饰符 |
| `ratio` | 是 | number | 倍率，可为负（做减益）；`0` 视为无效 |
| `operation` | 否 | string | 默认 `multiply_base`。可选 `addition`/`add`、`multiply_base`、`multiply_total`，大小写不敏感 |
| `uuid` | 是 | string | 标准 UUID 文本，**全局唯一**，是该规则的记账身份 |

### 3.4 校验结果表（照代码）

| 写错的情况 | 结果 | 有无日志 |
|---|---|---|
| 缺 `links` | 文件跳过 | 无 |
| 缺 `slot`/`curio`/`source`/`target`/`ratio`/`uuid` 任一 | 该条丢弃 | 有警告：`属性联动规则缺少必要字段…` |
| 四个 id 字段是空字符串 | 该条丢弃 | 无 |
| `ratio` 为 `0` | 该条丢弃 | 无 |
| `uuid` 不是合法 UUID | 该条丢弃 | 有警告：`uuid 非法` |
| `operation` 拼错 | **不报错**，回落 `multiply_base` | 无（最容易踩的静默坑） |
| `source`/`target` 属性未注册 | 该条静默无效 | 无 |
| `slot` 写错 / 佩戴者没这个槽 | 该条永不命中 | 无 |
| `curio` 写错 / 物品 id 不存在 | 该条永不命中 | 无 |
| `curio` 写成 `tcc:kongbai_zhijian` | 永不命中（自指排除） | 无 |
| 多余字段 | 忽略 | 无 |

### 3.5 三种 id 的写法

| 类型 | 格式 | 示例 | 去哪查 |
|---|---|---|---|
| 槽位 | Curios 槽位标识（无命名空间） | `tcc_slot` | 本 mod [TaczCurios.java#L125-L129](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/TaczCurios.java#L125-L129)、`data/curios/tags/items/*.json` |
| 饰品 | `namespace:path` 物品注册名 | `tcc:lethal_crit` | `data/curios/tags/items/<槽位>.json` 的 values |
| 属性 | `namespace:path` 属性注册名 | `taa:bullet_gundamage` | 见 [附录 A](#附录-a-可用属性-id-速查) |

## 4. 如何生成数据包

### 4.1 目录树

```
<世界存档>/datapacks/kongbai_links/
├── pack.mcmeta
└── data/
    └── tcc/
        └── tcc_links/
            └── kongbai_example.json
```

命名空间目录名（`tcc`）可以随便改，但 `tcc_links` 目录名**不能改**，它写死在 [AttributeLinkRegistry.java#L54](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/java/com/xlxyvergil/tcc/link/AttributeLinkRegistry.java#L54)。

### 4.2 pack.mcmeta（1.20.1 用 `pack_format: 15`）

```json
{
  "pack": {
    "pack_format": 15,
    "description": "空白之键联动规则"
  }
}
```

### 4.3 规则文件

见第 5 章示例，直接改 uuid 和 id 即可。

### 4.4 三种安装方式

| 方式 | 做法 | 适用 |
|---|---|---|
| 世界数据包（推荐） | 文件夹或 zip 丢进 `<存档>/datapacks/`，游戏内 `/reload` | 单个存档测试 |
| 整合包下发 | 把上面的 `data/` 与 `pack.mcmeta` 打进整合包的 `datapacks/` 或由整合包模组统一加载 | 发布 |
| 全局数据包 | 装 Paxi / OpenLoader 之类全局包加载模组，放进其配置目录 | 多存档共用 |

> 版本注意：`pack_format` 必须是 15（1.20 / 1.20.1）。写成 12/18 等会被当成不兼容包而**不加载**。想兼容多个版本可在 `pack` 里加 `supported_formats`。

### 4.5 验证步骤

1. `/reload`
2. 看服务端日志应出现：`[TCC] 属性联动规则已加载: 槽位数=1, 规则数=2` — 数字对不上说明有条目被上面第 3.4 表里的规则丢了。
3. `/datapack list` 确认包已启用（zip 与文件夹都会列出）。
4. `/give @s tcc:kongbai_zhijian` 戴上，把规则里写的饰品放进对应槽位，看 tooltip 是否出现 `已绑定饰品：…` 与蓝字加成。
5. 若 tooltip 只有 `未绑定联动饰品`：槽位名、饰品 id 或属性 id 写错，按第 6 章逐项排。

### 4.6 uuid 生成

每条规则必须唯一。生成一个：

- 在线生成器任选，或
- PowerShell：`[guid]::NewGuid().ToString()`
- Linux/macOS：`uuidgen`

> 模组**不再自带默认规则**（`tcc_links` 目录默认为空），所以新生成的 uuid 不会和自带数据撞车；只需保证你自己的规则之间不重复。同一个 uuid 被两条规则共用时，其中一条的修饰符永远清不掉（清理时按 uuid 去重），表现为"卸下饰品后还剩一截加成"。

### 4.7 热更新注意

- 改完 JSON 只需 `/reload`，在线玩家下一 tick 自动重算，无需重登。
- **删规则**安全：已写入的修饰符会按物品 NBT 里的旧快照清除。
- **改 uuid** 等于换了一条规则：旧 uuid 靠快照清掉，新 uuid 生效，不会残留。
- 修改后如果玩家数值看起来没变，先确认 `ratio`/`operation` 真的改了（幂等逻辑会在数值与运算方式都不变时跳过重建）。

### 示例 C：跨槽位 + 负倍率减益

```json
{
  "links": [
    {
      "slot": "tcc_tdk",
      "curio": "tcc:juezhe_zhi_jian",
      "source": "minecraft:generic.movement_speed",
      "target": "taa:inaccuracy",
      "ratio": -0.3,

      "uuid": "c07d3b58-91ae-4f26-a1c8-58e7b0492d36"
    }
  ]
}
```

### 常用换算思路

| 想要的效果 | source | target | operation |
|---|---|---|---|
| 暴击伤害 → 枪械伤害 | `attributeslib:crit_damage` | `taa:bullet_gundamage` | `multiply_base` |
| 攻击力 → 枪械伤害 | `minecraft:generic.attack_damage` | `taa:bullet_gundamage` | `multiply_base` |
| 移速 → 开镜速度 | `minecraft:generic.movement_speed` | `taa:ads_time` | `multiply_total`（注意快慢方向） |
| 攻速 → 射速 | `minecraft:generic.attack_speed` | `taa:rounds_per_minute` | `multiply_base` |
| 护甲 → 虚数抗性 | `minecraft:generic.armor` | `tcc:imaginary_damage_resistance` | `multiply_base` |
| 幸运 → 暴击率 | `minecraft:generic.luck` | `attributeslib:crit_chance` | `addition` |

> 加成的方向要自己确认：`taa:ads_time`、`taa:inaccuracy`、`taa:reload_time`、`taa:recoil`、`taa:weight` 这类属性**数值越低越好**，正倍率可能是削弱。写之前先看 [data/tcc/affixes](file:///d:/TaczAttributeAdd/TaczCurios%201.20.1/TaczCurios/src/main/resources/data/tcc/affixes/tcc_slot/attribute) 里同一属性的词条是加还是减。

## 6. 排错清单

按顺序自查，基本覆盖 90% 的"没生效"：

1. 文件路径是不是 `data/<ns>/tcc_links/xxx.json`（`.json` 后缀、`tcc_links` 拼写）。
2. 顶层是不是 `{"links": [ ... ]}`。
3. 六个必填字段齐不齐。
4. 日志里有没有 `[TCC] 属性联动规则已加载: 槽位数=…, 规则数=…`，计数对不对。
5. `slot` 是不是佩戴者真的拥有的槽位。
6. `curio` 是不是**完整**注册名（少了命名空间就永不命中）。
7. 属性 id 是否真的注册了（拼错静默失效，无日志）。
8. `operation` 拼写（`addition` / `multiply_base` / `multiply_total`）。
9. tooltip 显示的是否为 `已绑定饰品：…`；若为 `未绑定联动饰品`，问题一定在 5/6 两项。
10. 空白之键有没有真的戴在 `tcc_kb` 槽位上；**没有任何命中规则时它装不上去**。

## 7. 可直接使用的说明文案

### 7.1 物品描述（贴 wiki / 任务书 / 整合包说明）

> **空白之键**
>
> 裂隙级饰品，占用「空白之键」专属槽位。自身不提供任何固定属性，装备后绑定角色、死亡不掉落、可自由卸下。
>
> 它的作用是**属性重定向**：当某个指定饰品槽里装着指定饰品时，把你**自身**的某项属性总值按倍率转写到你的另一项属性上。那件饰品只是开关，不是数值来源。
>
> 例如：槽内装着《致命暴击》时，你**自己的暴击伤害总值**会按比例转化为枪械伤害；换上《千劫的图腾》后，你**自己的移动速度总值**会折算成开镜速度。
>
> 具体用哪个槽位、哪件饰品、转换哪两项属性与倍率为多少，由整合包的数据包决定。装备后 tooltip 会直接列出当前生效的「源属性 × 倍率 → 目标属性」以及实际加成数值。
>
> 提示：没有任何联动规则生效时，空白之键无法装备。

### 7.2 服主一行版

> 空白之键 = 属性重定向器：门控（指定槽位装着指定饰品）→ 佩戴者 source 属性总值 × 倍率 → 写入佩戴者 target 属性，规则写在 `data/<ns>/tcc_links/*.json`，`/reload` 即时生效。

### 7.3 更新日志写法

> **新增** 空白之键（`tcc:kongbai_zhijian`，`tcc_kb` 槽，裂隙级）：数据包驱动的属性联动饰品。指定槽位装着指定饰品时，把佩戴者自身某项属性的总值按倍率转写为另一项属性，规则可热更。无配套数据包时不可装备。
