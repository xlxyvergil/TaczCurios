# 饰品融合升级系统规划

## 概述

参考 Warframe 的 MOD 融合（Fusion）系统，为本模组 **tcc_slot 槽位**中的 **COMMON、UNCOMMON、RARE、EPIC** 稀有度饰品引入等级升级机制。玩家可以使用 **内融核心（CoreFusion）** 作为升级材料，按稀有度分级的成本公式，逐级提升饰品的属性效果。

> **范围限制**：
> - 仅限 **tcc_slot** 槽位的饰品
> - 仅限 **COMMON / UNCOMMON / RARE / EPIC** 稀有度
> - **RIFT** 稀有度、**tcc_3rd** 和 **tcc_tdk** 槽位的饰品不参与融合升级

---

## 一、核心材料

### 内融核心（CoreFusion）— 已存在

| 属性 | 值 |
|------|------|
| 注册名 | `tcc:core_fusion` |
| 中文名 | **内融核心** |
| 堆叠上限 | 64 |
| 当前用途 | 合成崩坏结晶（`tcc:collapse_crystal`） |
| 升级用途 | **作为通用升级材料**，消耗量按公式计算 |

内融核心可通过 **融合容器分解饰品** 获得。手持融合容器右键点击含饰品的格子，饰品被消耗，其内融核心价值按以下公式存入融合容器：

```
产出 CoreFusion = 
  COMMON:   (10 ÷ 3) × 饰品等级 + 5
  UNCOMMON: 7.5 × 饰品等级 + 10
  RARE:     12.5 × 饰品等级 + 15
  EPIC:     (1 + 饰品等级) × 20
```

各稀有度 0 级饰品可获得的 CoreFusion：

| 稀有度 | 0 级产出 | 满级产出 | 满级升级总消耗 | 回收占比 |
|-------|---------|---------|-------------|---------|
| COMMON | **5** | **21** | 310 | 6.8% |
| UNCOMMON | **10** | **70** | 5,100 | 1.4% |
| RARE | **15** | **140** | 30,690 | 0.5% |
| EPIC | **20** | **260** | 163,800 | 0.2% |

> 参考 Warframe 溶解 MOD 机制。低等级饰品可回收少量核心，高等级饰品可回收相对更多。整体回收率较低，鼓励玩家慎重选择升级对象。

其他获取途径（后续可扩展）：
- 敌人掉落
- 奖励箱/战利品表
- 村民交易

> **已移除**：裂隙碎银（`tcc:rift_silver`）的合成配方（9 内融核心 → 1 裂隙碎银）将被删除，改为直接使用内融核心作为升级材料，不再通过裂隙碎银进行随机饰品抽取。

### 融合容器（Fusion Vessel）— 新增

| 属性 | 值 |
|------|------|
| 注册名 | `tcc:fusion_vessel` |
| 中文名 | **融合容器** |
| 堆叠上限 | 1 |
| NBT 存储 | `tcc_fusion_count: int` — 存储的内融核心数量，默认上限 **655,200**（4×EPIC满级消耗） |
| 容量配置 | `fusionVesselCapacity` — Config 可调，默认 655,200 |
| 视觉反馈 | 使用原版**耐久条**显示当前存储进度（满耐久 = 满容量） |

**交互方式**（完全参考 TACZ 弹药盒 `overrideStackedOnOther` 模式）：

- **取出**：背包中手持融合容器，右键点击空格子 → 取出一组（64个）内融核心放入格子，不足则取全部剩余
- **存入内融核心**：背包中手持融合容器，右键点击含内融核心的格子 → 格子中整组（最多64个）内融核心被消耗，等量增加 `tcc_fusion_count`
- **分解饰品存入**：背包中手持融合容器，右键点击含饰品的格子 → 消耗饰品（1个），按分解公式计算产出 CoreFusion 并存入容器

> 类似 TACZ 弹药盒机制，容器仅存储 NBT 数字，突破堆叠上限限制。

## 三、升级成本公式

### 参考 Warframe 公式

Warframe 从 **0 级升至 r 级** 所需**内融核心（Endo）** 总计：`Cost(r) = EBC × (2^r - 1)`

其中：
- `EBC` = 基础内融核心消耗（Common=10, Uncommon=20, Rare=30, Legendary=40）
- `r` = 目标等级（从 1 开始，0→1 时 r=1）

### 本模组公式（与 Warframe 一致）

**从 0 级升至 r 级所需内融核心总数**：

```
Cost(r) = EBC × (2^r - 1)
```

其中 EBC（基础内融核心消耗）各稀有度不同：

| 参数 | COMMON | UNCOMMON | RARE | EPIC |
|------|--------|----------|------|------|
| EBC | **10** | **20** | **30** | **40** |

> 与 Warframe 完全一致（Common=10, Uncommon=20, Rare=30, Legendary=40）。

## 四、属性增长方式

### 线性增长（统一系数）

所有稀有度使用相同的线性公式：

```
等级 n 的实际属性值 = Config 基础值 × (1 + n × C)
```

其中：
- **Config 基础值** = 各饰品在 `TaczCuriosConfig.java` 中配置的数值（如 `riflingDamageBoost = 165.0`），**即 Lv.0 时的属性值**
- **C** = 增长系数，默认 **0.8**，可在 Config 中调整（详见[六、Config 配置](#六config-配置)）
- **满级值** = Config 基础值 × (1 + 最大等级 × C)

> **重要语义变更**：原有 Config 配置项（如 `riflingDamageBoost`）的数值含义由"满级值"变更为 **Lv.0 基础值**。  
> 游戏中 Tooltip 和实际效果均显示 **按当前等级计算后的实际数值**，而非 Config 中的原始基础值。

各稀有度的满级乘数：

| 稀有度 | 最大等级 | 满级乘数 (1 + max × C) |
|-------|---------|----------------------|
| COMMON | 5 | ×5.0 (1 + 5×0.8) |
| UNCOMMON | 8 | ×7.4 (1 + 8×0.8) |
| RARE | 10 | ×9.0 (1 + 10×0.8) |
| EPIC | 12 | ×10.6 (1 + 12×0.8) |

### 特殊处理

以下情况因代码实现方式不同，需单独处理：

#### 1. 异况增伤饰品（Condition Overload 等 4 件）

异况增伤是在 `CurioCombatEventHandler.onLivingHurt()` 中**直接对伤害乘算**的，不属于属性修饰符。

**升级方式**：升级后，在饰品 ItemStack 的 NBT 中记录等级，事件处理器读取等级并应用线性增长公式。

```
等级 n 的异况增伤值 = Config 基础值 × (1 + n × C)
```

其中 Config 基础值为各异况饰品在 `TaczCuriosConfig.java` 中的配置值，即 Lv.0 基础值。  
Tooltip 中显示按饰品当前等级计算后的实际数值，**调用 `FusionUpgradeUtil` 计算结果**。

示例（异况超量，EPIC，最大 12 级，Config 基础值 = +7.5%/种）：
- 0 级：**+7.5%**/种
- 5 级：+7.5% × 5.0 = **+37.5%**/种
- 12 级（满级）：+7.5% × 10.6 = **+80%**/种

#### 2. Buff 触发类饰品（镀层系列、尖刃弹头等）

Buff 触发类饰品不走属性增长公式。**饰品等级直接作为 Buff 等级**，Minecraft 自然处理效果缩放。

```
饰品等级 n → 触发 Buff 的 amplifier = n
```

- [饰品基础数值表.md](饰品基础数值表.md) 中的 Config 基础值（Lv.0）用于 Tooltip 展示
- Tooltip 中显示 **按当前等级计算后的实际数值**，调用 `FusionUpgradeUtil` 计算结果
- 实际 Buff 效果由 Minecraft 按等级自然缩放
- 持续时间与最大层数保持不变

示例（氩晶瞄具，Lv.0 基础爆头暴击 +15%）：
- 0 级：爆头触发 **Lv.0** Buff（+15% 暴击几率）
- 5 级：爆头触发 **Lv.5** Buff（Minecraft 自动处理）
- 10 级（满级）：爆头触发 **Lv.10** Buff

## 五、升级交互方式

### 合成台升级

采用 **合成台** 进行逐级升级，利用 `getRemainingItems()` 机制返还融合容器。

**合成配方（无固定形状，2×2 即可）**：

```
[合成格]
┌──────────────────────┐
│  饰品 (当前等级 Lv.N)      │
│  融合容器 (内有 ≥Cost 的   │
│     CoreFusion)           │
└──────────────────────┘
    ↓ 合成
┌──────────────────────┐
│  → 输出: 饰品 (Lv.N+1)    │
│  → 返还: 融合容器         │
│     (tcc_fusion_count 扣减 │
│      对应消耗，留在原位)   │
└──────────────────────┘
```

**流程说明**：

1. 玩家将待升级饰品和融合容器放入合成格
2. `matches()` 检查融合容器内 CoreFusion 数量是否 ≥ 升下一级所需
3. `assemble()` 生成升级后的饰品（Lv+1）到输出槽
4. `getRemainingItems()` 返还融合容器（扣除对应消耗，NBT 更新）
5. 容器始终留在合成格中，玩家重复合成即可逐级升级

**优点**：
- 原生 `getRemainingItems()` 支持，零 Mixin
- 玩家手动控制升级级数
- 兼容已附魔/已命名/有 NBT 的饰品

### 数据存储

- 等级信息存储在饰品 ItemStack 的 NBT 中：`tcc_fusion_level`
- 等级上限受饰品稀有度限制
- 融合后的饰品保留所有已有 NBT 数据（绑定、进化进度等）

### 互斥规则兼容

升级不影响互斥规则——低级和高级的同系饰品依然互斥（如膛线与并合膛线）。

## 六、Config 配置

### 原有饰品属性配置项（语义变更）

`TaczCuriosConfig.java` 中已有的各饰品属性配置项（如 `riflingDamageBoost = 165.0`）**语义变更为 Lv.0 基础值**。

> 原有配置项的名称、类型、位置均不改变，仅其数值含义由"满级值"改为"Lv.0 基础值"。  
> 游戏中 Tooltip 和实际效果均显示 `基础值 × (1 + 当前等级 × C)` 的计算结果。

### 新增融合升级配置项

在 `TaczCuriosConfig.java` 中新增以下配置段：

```toml
[fusion_upgrade]
# 属性增长系数（全局统一，默认 0.8）
# 公式: 实际值 = Config基础值 × (1 + 等级 × C)
growthCoefficient = 0.8

# EBC（基础内融核心消耗），各稀有度
# 公式: Cost(level) = EBC × 2^(level-1)
ebc = { common = 10, uncommon = 20, rare = 30, epic = 40 }

# 各稀有度封顶等级
maxLevel = { common = 5, uncommon = 8, rare = 10, epic = 12 }

# 融合容器容量上限（默认 655,200 = 4 × EPIC满级消耗）
fusionVesselCapacity = 655200
```

## 七、实现计划

### Phase 1：数据层
1. 新增 `FusionUpgradeUtil` 工具类 — 核心功能：
   - `getLevel(ItemStack)` — 读取 NBT `tcc_fusion_level`，无则返回 0
   - `setLevel(ItemStack, int)` — 写入 NBT 等级
   - `getMaxLevel(Rarity)` — 从 Config 读取稀有度封顶等级
   - `getGrowthCoefficient()` — 从 Config 读取增长系数 C
   - `getActualValue(double baseValue, int level)` — 计算 `baseValue × (1 + level × C)`
   - `getEBC(Rarity)` — 从 Config 读取 EBC
   - `getUpgradeCost(int targetLevel, Rarity rarity)` — 从 0 级升至 targetLevel 的总消耗：`EBC × (2^targetLevel - 1)`
   - `getDecompositionOutput(Rarity rarity, int level)` — 分解产出公式
   - 该工具类被**属性修饰符应用**、**Tooltip 显示**、**异况事件处理器**统一调用
2. 新增 Config 配置项（`TaczCuriosConfig.java`）：
   - `growthCoefficient` — 增长系数
   - `ebc` — 各稀有度 EBC
   - `maxLevel` — 各稀有度封顶等级
3. **现有饰品属性配置项语义变更**：原有配置项（如 `riflingDamageBoost`）数值含义由"满级值"变为"Lv.0 基础值"
4. 新增 **融合容器**（`FusionVesselItem`）— 实现 `overrideStackedOnOther`：
   - 右键空格子 → 取出一组（64个）CoreFusion，不足取全部剩余
   - 右键 CoreFusion 格子 → 整组（全部）存入容器，容器满则取到满
   - 右键饰品格子 → 按分解公式消耗饰品，存入等量 CoreFusion

### Phase 2：升级逻辑
5. 注册 **自定义合成配方**（无形状配方）— 饰品 + 融合容器 → 升级后的饰品 + 融合容器（返还）

### Phase 3：属性修饰符动态应用
6. 各饰品装备时，通过 `FusionUpgradeUtil.getActualValue()` 计算当前等级的实际属性值后应用修饰符

### Phase 4：异况适配
7. 异况增伤 4 件饰品的 NBT 等级读取与伤害乘算增强，调用 `FusionUpgradeUtil` 计算结果

### Phase 5：Tooltip 显示
8. 所有饰品 Tooltip 显示当前等级和计算后的实际属性值
   - Buff 类、异况类、普通属性修饰符类均通过 `FusionUpgradeUtil` 获取计算值
   - 显示格式：`属性名: +计算值%`
